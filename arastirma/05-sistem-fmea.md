# NutriScan — Sistem, Veri ve AI FMEA

## 0. Nasıl okunur

**Puanlar 1–5, önlem öncesi (doğal risk), tümü [değerlendirme].**

| Ölçek | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| **O** — Olasılık | çok düşük | düşük | beta boyunca (Nisan–Mayıs, 20–40 hane) bir kez beklenir | ayda birkaç kez | haftalık / sürekli |
| **Ş** — Şiddet | kozmetik | geçici işlev kaybı, kolay telafi | yanlış öneri, para/zaman kaybı, güven kaybı | hukuki ihlal (KVKK, lisans), hesap ele geçirme, geniş veri bozulması | kullanıcının sağlığına zarar (alerjen yanlış negatifi) ya da özel nitelikli veri sızıntısı |
| **T** — Tespit zorluğu | otomatik ve anında (CI kapısı, alarm) | otomatik ama gecikmeli (nightly, pano) | kullanıcı bildirimi ya da manuel inceleme | yalnız hedefli denetimle | sessiz |

**RPN = O × Ş × T** (1–125). **Eylem kuralı:**
1. **Ş = 5 → RPN'den bağımsız** zorunlu önlem + otomatik test (severity override).
2. RPN ≥ 40 → beta öncesi kapanır.
3. RPN 20–39 → backlog'da planlı.
4. RPN < 20 → izlenir.

Önlem hücresi üç parça: **Önle** (önleyici) · **Yakala** (tespit) · **Kurtar** (kurtarma). `K01…K20` → §8'deki mimari kurallar. Köşeli parantezli etiketler: `[LLM01]` OWASP LLM Top 10 2025 · `[ASI06]` OWASP Agentic Top 10 2026 · `[API1]` OWASP API Security Top 10 2023.

Artık risk (residual) puanlaması Faz 3 ADR'lerinden sonra yapılacak. Bu dosya yaşayan dokümandır: her yeni özellik PR'ı "FMEA'da satırı var mı, Ş=5 ise test ID'si var mı?" sorusundan geçer.

### 0.3 Güven sınırları
```
[Güvenilmeyen girdi]  etiket/raf/buzdolabı fotoğrafı · fiş (foto/PDF/XML) · OFF kaydı · topluluk katkısı · tarif
        │
        ▼  dosya sandbox'ı (K14) → karantina çıkarıcı: LLM/VLM, araçsız, yalnız JSON şema (K04)
        ▼  şema doğrulama + veri kalitesi kapısı (K11)
[Deterministik çekirdek, TR]  kural motoru · optimizasyon + bağımsız doğrulayıcı (K10) · fiyat · kiler
        │
        ▼  Decision Record (değişmez, sürümlü, K08) ─────────────►  UI hüküm kartı (yalnız DR'den çizilir, K01)
                                                                          ▲
[Kullanıcı mesajı/ses] → maskeleme + egress kapısı (K06) → Asistan LLM ──┘ anlatım metni, claim checker'dan geçer (K02)
                         (yer tutucular: ÜYE_2, KISIT_7)   okuma araçları · onaylı yazma · dış iletişim yok (K05)
```
Bu tasarım Willison'ın "lethal trifecta"sının (özel veri + güvenilmeyen içerik + dışarı iletişim) üçüncü bacağını keser ve CaMeL / "Design Patterns for Securing LLM Agents" makalelerindeki **plan-then-execute + dual LLM (karantina)** desenlerine dayanır (Kaynaklar).

**İki küme var [değerlendirme]:**
1. **Alerjen yanlış negatifi altı ayrı yoldan gelebiliyor:** sözlük, normalizasyon, veri eksikliği, görsel okuma, eski veri, LLM anlatımı. Tek tek yama yetmez. Çözüm tek ilke: **güvenlik monotonluğu + "Doğrulanamadı"** (K03). Belirsizlik her zaman riski artırır; hiçbir olasılıksal bileşen güvence veremez.
2. **Sağlık verisi beş kanaldan yurt dışına çıkabiliyor:** LLM, VLM görseli, push bildirimi, crash/log/trace SaaS, test ortamı ve AI kodlama ajanları. Çözüm **tek egress kapısı** (K06) + prod verisinin prod dışına çıkmaması (K19).

## 9. Test stratejisi taslağı

İlke: **güvenlik-kritik metriğin eşiği yok, sıfır.** Alerjen yanlış negatifi, kısıt gevşetme, maskeleme kaçağı ve kiracı sızıntısı ya 0'dır ya da sürüm çıkmaz. Diğer metrikler eşikli.

## 10. SLO önerileri

Tümü **[değerlendirme]**; ölçülmedi. Faz 7'de yük testiyle kalibre edilecek. Ürün tanımındaki hedefler (`plan/urun-tanimi.md` §8) korunmuştur.

**Düşük trafik notu:** 20–40 hanelik beta'da 28 günlük pencerede az olay birikir; oranlar gürültülü olur. SLI'ler hem gerçek trafikten hem 1–5 dakikalık **sentetik problardan** (bilinen barkodu tara, bilinen planı hesapla, asistana sabit soru sor) beslenir.

### 10.1 Erişilebilirlik (28 günlük kayan pencere)
| Hizmet | SLI | Hedef |
|---|---|---|
| Çekirdek API (auth, tarama kararı, liste, takas, plan okuma) | Başarılı istek oranı (5xx + timeout başarısız sayılır) | **%99,5** (≈ 3,4 saat / 28 gün) |
| Asistan | Tur "kullanıcıya bir cevap döndü" ile bitti (LLM'siz fallback dahil) | **%99,0** |
| Asenkron görüntü işleri | 2 dk içinde son duruma (başarı / Doğrulanamadı / tekrar çek) ulaşan iş oranı | **%98** |
| Admin paneli | Başarılı istek oranı | %99 |

### 10.2 Gecikme
| Akış | Hedef |
|---|---|
| Rafta karar, katalogdaki ürün (uçtan uca, RUM) | **p95 ≤ 1,5 s** (ürün tanımı); sunucu p95 ≤ 400 ms, p99 ≤ 1 s |
| Akıllı Takas (≤ 60×20) | **p95 ≤ 1 s** (ürün tanımı); çözücü timeout oranı ≤ %0,5 |
| Haftalık plan/menü (async) | p95 ≤ 30 s, bildirimle |
| Asistan ilk token / ilk "adım" olayı | p95 ≤ 2 s / ≤ 1 s |
| Asistan, araç kullanan tur tamamlanması | p95 ≤ 8 s |
| Etiket çıkarımı / fiş çıkarımı | p95 ≤ 10 s / ≤ 25 s |

### 10.3 Doğruluk ve güvenlik (sürüm kapısı + prod SLI)
| Metrik | Hedef |
|---|---|
| Alerjen golden set yanlış negatifi | **0** (hata bütçesi yok) |
| Property: 10k hane × sepet alerjen ihlali | **0** |
| NL→IR güvenlik-kritik hata (sert kısıt düşmesi/gevşemesi) | **0**; slot doğruluğu ≥ %90 |
| Maskeleme kaçağı (eval) / prod kanarya bulgusu | **0 / 0** |
| Decision Record kapsamı (görünen her hüküm ve öneri) | **%100** |
| Kullanıcıya ulaşan desteksiz hüküm cümlesi | **0**; claim checker'ın yakaladığı blok oranı ≤ %0,5 tur (üstü = prompt/model sorunu) |
| Optimizasyon son doğrulayıcı ihlali | **0**; olursuzlukta gevşetme önerisi üretme ≥ %95 |
| "Doğrulanamadı" oranı — pilot katalog ürünleri | ≤ %5 (genel taramada bilgi amaçlı izlenir, hedef değil) |
| Etiket çıkarımı: alerjen ifadesi recall (eval) | ≥ %98 [ölçülünce kalibre] |
| Fiş: %95 hassasiyette kapsama | Zincir bazında raporlanır (ürün tanımı) |

### 10.4 Tazelik
| Metrik | Hedef |
|---|---|
| OFF mirror yaşı | ≤ 48 saat (zamanın %99'u) |
| Pilot katalog fiyat yaşı | Medyan ≤ 14 gün; > 30 gün fiyat optimizasyona girmez |
| Kural paketi | Pod'lar arası hash tutarlılığı %100; mobil offline paket ≤ 7 gün |
| Kural/radar güncellemesinden etkilenen haneye bildirim | ≤ 24 saat |

### 10.5 Operasyon ve güvenlik hedefleri (SLO değil, taahhüt)
- **RPO ≤ 15 dk, RTO ≤ 4 saat** (beta); aylık tatbikatla kanıtlanır.
- Kritik CVE ≤ 7 gün, yüksek ≤ 30 gün.
- Güvenlik olayında triage ≤ 12 saat; **KVKK bildirim kararı ≤ 48 saat** (72 saatin içinde tampon).
- Sır rotasyonu ≤ 90 gün; sızıntıda ≤ 1 saat.
- Hesap silme ≤ 24 saat (yedeklerde crypto-shredding); m.11 başvurusu yasal olarak 30 gün, hedef 7 gün.

### 10.6 Hata bütçesi politikası
- Bir hizmetin bütçesi tükenirse o bileşende yeni özellik durur, güvenilirlik işi öne alınır.
- Güvenlik metriklerinin (10.3'teki "0" hedefleri) bütçesi yok: tek ihlal = sürüm durur + olay kaydı + regresyon testi.
- Alarmlar burn-rate tabanlı (çok pencereli); OPS-03'teki "sayfa/bilet" ayrımıyla.

## 11. Levent'e açık sorular (varsayım yapılmadı)
1. **LLM sağlayıcısı ve konumu:** yurt dışı API + maskeleme mi, TR'de barındırılan açık ağırlıklı model mi? K06'nın maliyeti ve LLM-10'un artık riski buna bağlı.
2. **Barındırma sağlayıcısı** (TR) ve yedeğin ikinci konumu.
3. **Kimlik doğrulama:** e-posta + parola mı, passkey mi, SMS OTP mi? SMS, SIM swap ve SMS pumping riskini getirir.
4. **Hane içi görünürlük:** yetişkinler birbirinin kısıtlarını varsayılan olarak görür mü? Davet onayı yalnız sahipte mi?
5. **Ham görsel saklama süresi** (önerim 72 saat) ve OFF'a görsel katkısı yapılacak mı?
6. **Beta nöbeti:** 3 kişilik ekipte kim, hangi saatlerde? Sınav haftaları nasıl kapanacak?
7. **Eski repodaki sırlar** iptal edildi mi, repo public mi? (DURUM.md'de de açık; K15'in ilk adımı.)
8. **Offline mod** (katalogda C önceliği) yapılacak mı? KUR-04'ün kapsamını belirliyor.
9. **Raf fotoğrafı özelliği:** GOR-06 önerisini (rafta yeşil yok, yalnız kırmızı/gri) ürün olarak kabul ediyor musun? Wow etkisini bir miktar düşürür, sağlık riskini ciddi düşürür.
